# CLAUDE.md の書きかた

## 前提

CLAUDE.md は **毎セッション、全文が読まれる**。だから:

- 長さは費用。400 行の CLAUDE.md は、毎回 400 行ぶん払っている
- 間違いは害。存在しないパスが書いてあれば、Claude はそれを探しに行く
- 一般論は無駄。「読みやすいコードを書く」は、書かなくても同じ

**判定はひとつ: それが無いと Claude が間違うか。** 間違わないなら消す。

## 書くもの

上から順に。**各節は無ければ省く。**

| 節 | 中身 | 目安 |
|---|---|---|
| 何をするものか | 1〜3 行。誰が何のために使うか | 3 行 |
| 動かす | 実際に通るコマンド。ビルド / 起動 / テスト / 整形 | 8 行 |
| どこに何があるか | ディレクトリごとに 1 行。**深追いしない** | 12 行 |
| 決まりごと | 守らないと壊れるものだけ。理由を 1 行添える | 15 行 |
| 触らないもの | 生成物・秘密・外部から同期されるもの | 5 行 |
| 体制 | どの役が何を見るか。1 役 1 行 | 8 行 |

全体で **120 行**を目安にする。超えたぶんは `docs/` に出して、CLAUDE.md からは
1 行で指す (「設計の詳しい話は `docs/architecture.md`」)。
**出し方と、何を CLAUDE.md に残すかは skill `single-source`。**

### 「決まりごと」に書けるもの

守らないと**壊れる**ものだけ。好みは書かない。

```markdown
- DB のスキーマを変えたら `npm run migrate:gen` を回す。手で書いた
  マイグレーションは本番で順番が狂う
- `lib/generated/` は触らない。`build_runner` が上書きする
- 日付は必ず UTC で保存する。表示のときだけ地方時に直す
```

理由 (「〜すると壊れる」) が書けないなら、それは決まりごとではなく好み。

## 書かないもの

| 書かない | なぜ |
|---|---|
| README の写し | 二重管理になり、片方が必ず古くなる (skill `single-source`) |
| 一般論 (「テストを書く」「可読性を大切に」) | 無くても行動が変わらない |
| 実装の履歴・変更の経緯 | `docs/archive/` か git log の仕事 |
| これからやること | `docs/TODO.md` の仕事。CLAUDE.md は**いまの姿**だけ |
| コードの中身の説明 | コードを読めば分かる。古くなるだけ |
| 褒め言葉・意気込み | 1 行も要らない |
| 存在しないパス・通らないコマンド | **害。必ず確かめてから書く** |

## 確かめてから書く

書いたパスとコマンドは、**その場で確かめる**。

```bash
ls <書いたパス>            # ディレクトリ / ファイルが実在するか
<書いたコマンド> --help    # そのコマンドが本当に通るか
```

claude-keeper が入っているなら、参照切れは機械が拾う (`/claude-keeper:check`)。
入っていなくても**書いたパスは自分で `ls` する。**存在しないパスは害。

## 生成した部分に印を付ける

`/claude-keeper:refresh` が書き直してよいのは、印の内側だけ。

```markdown
<!-- claude-keeper:generated -->
## 動かす
...
<!-- /claude-keeper:generated -->

## このリポジトリだけの事情

(ここは手で書いた。refresh は触らない)
```

- 印の**外側は絶対に書き換えない**。消したくなったら、消してよいか聞く
- 印が 1 つも無い既存の CLAUDE.md を作り直すときは、**まず全文を読み、
  手で書かれたと思われる節を洗い出して見せてから**印を付ける
- 印の中に、手で書いたものを取り込まない

## 文体

文体は skill `docs-style` に従う。それが無ければ最低限:

- 見出しを飾らない (「📚 概要」「はじめに」は不要)
- 同じことを二度書かない (要約 → 本文 → まとめ、をやらない)
- 箇条書きに文を詰め込まない。1 項目 1 主張
- 「〜することができます」ではなく「〜できる」

## 直したあと

claude-keeper が入っているなら `/claude-keeper:check` を回す。生成部分に手が入った
ことを控え直すのは `/claude-keeper:refresh` の仕事で、控えないまま作り直すと
手で書いた部分が消える。
