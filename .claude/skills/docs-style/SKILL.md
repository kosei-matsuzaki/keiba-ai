# docs の文体規約

ドキュメントは**読む人の時間を節約するため**にある。行数が増えるのは、たいてい
書き手が考える手間を読み手に押しつけているとき。以下は禁止事項のリスト。
「禁止」と書いてあるものは、書かない・見つけたら消す。

## 1. 言い回しの禁止

| 禁止 | 代わりに |
|---|---|
| 〜することができます / 〜することが可能です | 〜できる |
| 〜を行う / 〜を実施する / 〜を実行することにより | その動詞そのまま(「実行する」「消す」) |
| 重要な点として / 注意点としては / ポイントは | 前置きを消して内容から書く |
| 〜と言えるでしょう / 〜と考えられます / 〜かもしれません | 断定する。断定できないなら根拠か条件を書く |
| 効率的に / 柔軟に / シームレスに / 堅牢な / 最適化された / モダンな | 具体的な数値・条件・比較対象。書けないなら形容ごと消す |
| 本ドキュメントでは〜について説明します | 消す。見出しが役割を果たしている |
| これにより、〜が可能になります | 「だから〜できる」か、因果が自明なら消す |
| ぜひ活用してください / 参考にしてください | 消す。読み手に呼びかけない |
| 〜な方は / 〜したい場合は(が3回以上続く) | 表にする |

そのほか:

- **語尾を混ぜない。** 常体か敬体のどちらかに揃える。既存ファイルの語尾に合わせる
- **絵文字は見出しに付けない。** 使うのは警告 1 種類までにとどめる
- **太字は 1 段落 1 箇所まで。** 全部太いのは全部普通と同じ
- **英語の直訳をしない。**「〜のための」「〜において」「〜に関して」は削れる

## 2. 構造の禁止

- **中身のない節を作らない。** 「はじめに」「概要」「まとめ」だけの節は消す。
  節の中身が 2 行なら、その節は要らない
- **同じことを 3 回書かない。** 冒頭の要約 → 本文 → 末尾のまとめ、は 1 回でいい
- **見出しは 3 階層まで。** `####` が要るなら、その節はファイルを分けるか表にする
- **箇条書きのネストは 1 段まで。** 2 段以上になったら表にする
- **並列で 5 項目以上、各項目に説明が付くなら表にする。** 箇条書きで延々並べない
- **コードブロックの直前直後に、その内容の日本語訳を置かない**

## 3. 内容の禁止

- **コードを見れば分かることを書かない。** 関数名の和訳、引数の列挙、
  ディレクトリ名の言い換え。書くのは「なぜそうなっているか」
- **一般論を書かない。**「テストは重要です」「適切に設計しましょう」。
  このリポジトリでだけ成り立つことを書く
- **実装履歴・試行錯誤を本文に混ぜない。** 「最初は A を試したが B にした」は
  `archive/` 配下にだけ書く。仕様書・設計書は**いまの姿**だけを書く
- **「今後の課題」を各ファイルに散らさない。** 残作業は `TODO.md` 1 箇所に集める
- **存在しないファイル・コマンド・URL を書かない。** 書く前に実在を確かめる
- **日付のない記録を残さない。** 記録に日付がなければ後から捨てられない

## 4. 残すもの

削るときに、これらは守る。ドキュメントの価値はここにしかない。

- **なぜそう決めたか。** 選ばなかった案と、選ばなかった理由
- **ハマった罠と回避法。** 再現条件つきで
- **やらないと決めたこと。** これがないと同じ議論を繰り返す
- **そのまま動くコマンド。** コピーして貼れば動く形で
- **壊れる操作への警告。** 失うと復旧できないもの、順序を守るべき手順

## 5. 直すときの手順

1. 上から読み、**2 節と 3 節に当たる塊をまず消す**(言い回しより先に構造)
2. 残った本文に 1 節の言い換えを当てる
3. 消した結果、見出しの下が空になったら見出しも消す
4. **行数を報告する。** 「420 行 → 180 行」のように、何をどれだけ削ったか示す
5. 削った中に「なぜ」が含まれていたら、それだけは 1 行に圧縮して残す

削るときの原則: **迷ったら消す。** 消して困ったら git から戻せる。
ただし 4 節に挙げたものだけは、迷ったら残す。
