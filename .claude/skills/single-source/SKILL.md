# 同じ事実は 1 か所に置く

## なぜ

二重管理の害は「冗長」ではない。**片方が必ず古くなり、読んだ人にはどちらが
正しいか分からない**ことにある。

- 書いた本人は両方を覚えているので、どこにあっても引ける。**害を受けるのは
  初めて読む人と、半年後の自分**
- 直すとき、片方しか直らない。**片方だけ直った状態がいちばん見つけにくい**
- 消すときも片方しか消えない。**残ったほうが「まだ有効な仕様」として読まれる**

だから「両方に書いておけば親切」は成り立たない。**親切なのは、1 か所に置いて、
そこを指すこと。**

## 同じ事実かどうかの見分け方

字面ではなく、**変わるときに一緒に変わるか**で決める。

| 問い | 同じ事実 |
|---|---|
| 実装を変えたとき、両方直さないと嘘になるか | **はい → 1 か所にする** |
| 片方だけ直しても、どちらも正しいままか | いいえ → 別の事実。そのままでよい |

```
CLAUDE.md 「ビルドは npm run build」
README.md 「ビルドは npm run build」
    → 同じ事実。スクリプト名を変えたら両方嘘になる。1 か所にする

CLAUDE.md 「ID 系を FEATURE_COLUMNS に入れない。暗記でリークする」
docs/design.md 「特徴量は builder.py に集約し、抽出器を per-domain に分けた」
    → 別の事実。前者は禁止事項、後者は設計判断。両方あってよい
```

**言い換えて写したものも二重管理。**「表現が違うから別」ではない。

## 事実の持ち主を決める

**先に持ち主を決めてから書く。**書いてから寄せ先を探すと、たいてい両方残る。

| 事実の種類 | 持ち主 |
|---|---|
| 何をするもので、誰のためか | `README.md` |
| 動かすコマンド (ビルド / 起動 / テスト / 整形) | `CLAUDE.md`。README は概要だけ |
| 守らないと壊れる決まりごと・既知の罠 | `CLAUDE.md` |
| いまの仕様。やらないと決めたこと | `docs/spec.md` |
| どう作ってあるか。設計判断とその理由 | `docs/design.md` |
| 見た目の規定 (配色・余白・字送り・動き) | `docs/design.md` |
| いまは直さないと決めたこと | `.claude/judgments.yml` |
| 実装履歴・試したこと・没案 | `docs/archive/` |

置き場所の一覧は規約 `.claude/policy.yml` の `docs.layout`。
**持ち主が `layout` に無いなら、`layout` のほうに足す。**既にある文書へ
押し込むと、次は「1 つの文書に 2 つの話」になる。

## 写す代わりに指す

```markdown
<!-- ✗ 二重管理 -->
## デザイン
配色は Material 3 のシード色 #2B6CB0 から生成する。余白は 4 の倍数。
角丸は 12px。本文は 16sp / 行間 1.5。……(20 行)

<!-- ○ 1 行で指す -->
## デザイン
配色・余白・字送りの規定は [docs/design.md](docs/design.md)。**推測で足さない。**
```

指し方の型:

- **相対パスのリンク 1 本。**「詳しくはドキュメントを参照」は指していない
- **要約を添えない。**添えた要約がそのまま次の二重管理になる。
  添えてよいのは「読まないと何を間違えるか」の一言だけ
- 指す先が長いなら**節の見出しまで指す** (`docs/design.md#配色`)

## 写してよい例外

**2 つだけ。**それ以外は指す。

| 例外 | 条件 |
|---|---|
| 手順の中でそのまま動かすコマンド | 指しに行かせると手順が切れる。**コマンドは写す** |
| 読まずに操作すると壊れるもの | 警告は目に入る場所に置く。**ただし本文は 1 か所** |
| 独立して動く必要があるもの | 写し先が写し元を読めない場合(雛形・配布物・生成物) |

例外にするときは、**写した側に「正はどこか」を書く。**コマンドの写しは、
**正のほうを直したら写しも直す**(片方だけ直ると、動かないコマンドが残る)。

```markdown
> 破壊的操作。手順の正は [docs/operations.md](docs/operations.md)。
```

## 切り出すとき

長い節を `docs/` へ出すときの手順。**順番を守る。**

1. 出す先を決める(上の表)。`docs.layout` に無ければ**先に足す**
2. **全文を移す。要約しない。**要約したぶんはその場で失われる
3. 元の場所に**「どこへ行ったか」の 1 行**を残す。消しっぱなしにしない
4. 索引 (`docs/README.md`) に 1 行足す
5. 移した先を指しているリンクが他に無いか grep する

## 確かめる

書き終えたら、**その事実が他の文書にも書かれていないか**を先に grep する。

```bash
grep -rn "<書いた事実の特徴的な語>" README.md CLAUDE.md docs/
```

claude-keeper が入っているなら、字面がそろっているものは機械が拾う:

```bash
K=$(ls ~/.claude/plugins/cache/*/claude-keeper/*/scripts/k.py 2>/dev/null | head -1)
[ -n "$K" ] && python3 "$K" check --only docs
```

**機械が拾うのは字面がそろっているものだけ。**言い換えて写したものは出ない。
それを見るのは役 `duplication-auditor` と `/docs`。
