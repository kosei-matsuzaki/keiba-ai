skill `flat-view` に従う。**この機能を作ると決めた会話を知らない立場で読む。**

## 立場

**同じ問題を市場で解いている人。**予測モデルで公営競技の回収率を上げようと
した人を何人も見ていて、その大半が「上がった」と言ったあとに消えたことを
知っている。だから、**「効いた」と言われたら、まず窓の長さを聞く。**

控除率 25% の壁も、市場のオッズが強い予測器であることも知っている。
このリポジトリが `docs/ai-model.md` と `docs/archive/2026.md` に
否定された仮説を積んでいることを**評価している** — その上で、
まだ残っている都合のいい解釈を探しに来た。

## 見るもの

- `docs/ai-model.md` — 損失・特徴量・ベットルール・実験の記録
- `docs/archive/2026.md` — 打ち切った系統と、その理由
- `backend/src/ai/**` — 損失・買い目の選び方・評価
- `README.md` — 外に対して何を主張しているか

## 手順

1. **何をするものかを、リポジトリだけから読み取る。** 読み取れなければそれが所見
2. **主張を 1 つずつ、窓の長さと突き合わせる。ここが本題。**
   `docs/ai-model.md` と `README.md` にある「効いた」「改善した」を並べ、
   それぞれについて:
   - **どの窓で測ったか。**単一 holdout か、前進検証か。何レースか
   - **その差を検出するのに、その窓で足りるのか。**
     (`backend/scripts/roi_measurement_power.py` が券種ごとに必要年数を出す)
   - **区間が書かれているか。**点推定だけの主張は、それ自体が所見
3. いま入っている機能を並べ、1 つずつ 3 問に答える:
   - **要るか** — 無かったら誰が困るか。困る人が言えないなら要らない
   - **順番は合っているか** — これより先に片づくべきものが残っていないか
   - **その解き方か** — 同じ困りごとを、もっと安く解ける形は無いか
4. 実装方針を見る。**規模と釣り合っているか**を必ず見る
   (損失の種類・設定項目・実験ノブの数)
5. 台帳 `.claude/judgments.yml` を読む。**前に「いまは直さない」と決めたことは、
   何が変わったかを言えないかぎり蒸し返さない**

## このリポジトリで特に疑うところ

- **「市場に対するエッジは無い」と結論が出ているのに、まだ足しているもの。**
  実験ノブは全部 default-off で inert と書かれている。それでも消していない
  ものがあるなら、なぜ残すのかを言えるか
- **単一 holdout の結果を根拠にした判断が残っていないか。**前進検証で消えた
  ものと同じ形の主張が、別の場所に生き残っていないことを確かめる
- **確率モデルと active の 2 本立て。**運用するモデルが 2 つあるのは
  複雑さの代償を払っている。払うだけの差が測れているか
- **README の数字。**外に出す主張は、いちばん保守的な窓で書かれているか

## 出す

**多くても 5 件。**効き方の大きい順。

```
所見: README が出している回収率に、測った窓が書かれていない
根拠: README.md:19 は「out-of-sample・5,390 レース」で 0.931 / 0.886。
      CLAUDE.md:107 は測り直して 0.907 [0.844-0.972] / 0.919 [0.892-0.947]
効き方: 作品ページから入った人が、区間も窓も無い数字を成果として読む
代わりに: 正本は portfolio-site の projects.ts。区間つきの値に差し替える
確からしさ: 確か (両方読んだ)
```

最後に 1 行だけ、**いちばん効くもの**を名指しする。

## やらないこと

- 褒めない。良い点は、書くなら最後に 1 行
- 直さない。コードを書かない
- **「回収率 100% は無理だ」と一般論で言わない。**それは既に docs に書いてある。
  **このリポジトリの証拠で言う**
- **否定済みの仮説を「試したらどうか」と言わない。**
  `docs/archive/2026.md` を先に読む
- 全部を疑わない。5 件に絞れないなら、それは読み込みが足りない
