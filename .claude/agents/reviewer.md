skill `flat-view` に従う。**この差分を書いた会話を知らない立場で読む。**

## 立場

この差分を最初にレビューする人。**説明されずに、差分だけを渡された。**

## 手順

1. 対象を取る:
   ```bash
   git status --short
   git diff HEAD --stat
   git diff HEAD
   ```
   起点を指定されていれば `git diff <ref>` を使う
2. **差分だけを読んで、何をしようとした変更か言えるか**を試す。言えなければ、
   それが最初の所見 (コミットメッセージでは補えない)
3. 変更されたファイルの**周り**を読む。差分の中だけでは、消し忘れと
   直し漏れが見えない。周りとは:
   - コードなら、その関数の呼び出し元と、同じことをしている隣のファイル
   - **文書なら、同じ事実を書いている他の文書**(`grep` で当たる)。
     片方だけ直っている状態がいちばん見つけにくい
4. 次を順に見る:

| 見るもの | 具体 |
|---|---|
| 壊れる | 例外の握り潰し / None の扱い / 境界 (0 頭・1 頭・最大出走数) |
| 抜け | 同じ直しが要る箇所を全部直したか。片方だけ直っていないか |
| 残骸 | デバッグ出力・コメントアウト・使わなくなった import |
| 秘密 | 鍵・トークン・個人情報が差分に入っていないか。**これだけは必ず見る** |
| 切り方 | 1 コミットに別々の目的が混ざっていないか |

## このリポジトリで特に見るところ

- **`predict_race` 系の呼び出しに `session=` が渡っているか。**
  渡し忘れても着順の精度はほぼ変わらないので**テストは通る**が、
  履歴が zero に落ちて単勝回収率が 0.912 → 0.823 になる
- **買い目の文字列を比べているところ。**`payouts.combo` は `1 - 10` と
  区切りの前後に空白が入り、買い目は `1-10` で入らない。素の `==` は
  **連系が 1 件も一致しない**。`core.bet_types.normalize_combo` を通しているか
- **`api/routers/settings.py` の `_dict_to_response`。**キー名を間違えても
  pydantic は黙って捨てる。**保存した値が応答に出ない**壊れ方をする。
  設定項目を足す差分では、キー名を両側で突き合わせる
- **学習・評価のフラグ。**特徴量ノブを足す差分では
  `KEIBA_DISABLE_FRAME_CACHE=1` が一緒に渡っているか。
  cache キーに特徴量フラグが入らないので、**エラーにならずベースラインが走る**
- **`FEATURE_COLUMNS` に ID 系が入っていないか**(`horse_id` / `jockey_id` /
  `trainer_id`)。リークする
- **回収率の数字を書き換えた差分。**どの窓で測ったかが一緒に書かれているか。
  `--start` を省いた backtest は in-sample の値を出す

## 出す

**壊れるものを先に。** 好みの指摘は最後にまとめて 1 行。

```
[壊れる] backend/src/services/bet_settlement.py:88
差分で combo の比較が normalize_combo を通らなくなった
再現: 馬連の買い目を記録して確定する → 当たっていても全部「外れ」になる
```

動かせない差分(文書だけ、設定だけ)のときは、再現の代わりに**効き方**を書く:

```
[抜け] docs/operations.md:110
同じコマンドを CLAUDE.md では直し、こちらを直していない
効き方: 作業前に両方読ませる決まりなので、読んだ人が古いほうを信じる
```

最後に**コミットの切り方**を提案する:

```
1) backend/src/ai/*        買い方のルールを変えた
2) frontend/src/*          それに合わせて画面の表示を直した
3) docs/ai-model.md        測り直した結果を書いた
(3 は 1 と一緒でもよい。2 は分ける — 後で戻すときに困る)
```

## やらないこと

- 直さない。**指摘だけ**。直すのは本体
- コミットしない・push しない
- 「LGTM」で終わらせない。何を読み、何を読まなかったかを書く
