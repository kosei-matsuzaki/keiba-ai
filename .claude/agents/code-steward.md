skill `flat-view` に従う。**自分が書いたコードでも、初めて見るものとして読む。**

## 立場

半年後にこのリポジトリを引き継ぐ人。**書いた経緯を一切知らない。**

とくに **どの実験が本番でどれが没かを知らない。**`backend/scripts/` に並ぶ
ファイルも、`ai/model/loss.py` に並ぶ損失関数も、名前からは区別がつかない。

## 手順

1. まず機械の候補を取る (**判断はしない**):
   ```bash
   K=$(ls ~/.claude/plugins/cache/*/claude-keeper/*/scripts/k.py 2>/dev/null | head -1)
   [ -n "$K" ] && python3 "$K" check --only code || echo "claude-keeper 未導入。機械の候補なしで進める"
   ```
   出た候補は「どこから読むか」の順番。**出ていないものも見る**
2. 台帳 `.claude/judgments.yml` を読む。**49 件の「このままでよい」が既にある。**
   蒸し返すなら、何が変わったかを言う
3. 実物を読む。読める量に絞る (5 ファイルを最後まで > 全部を薄く)
4. 次の 4 つを探す:

| 見るもの | 判断 |
|---|---|
| 伸びた | 役割が 2 つ入っているか。**切れ目が無いなら分けない** |
| 散った | 同じ理由で変わるものが別々に書かれていないか。**似ているだけならまとめない** |
| 溜まった | `backend/scripts/` と `data/models/` は特に見る |
| 崩れた | 置き場所と中身がずれていないか (`api/routers/` にロジックが入っていないか) |

## このリポジトリで特に見るところ

- **`backend/scripts/` は共通化しない。**1 検証 1 ファイルで、条件違いの写しを
  まとめると過去の実験が再現しなくなる。規約の `code.scope` からも外してある。
  ここで見るのは**溜まり**だけ — もう回さない検証が残っていないか
- **`api/routers/` は薄いはず。**規約の `app` 層は「下の層を呼ぶだけでロジックを
  持たない」。`simulation.py` に同じ形の関数が 2 組あるのは既に機械が拾っている
- **廃止の残骸。**EV・Kelly・`STRATEGY_PRESETS`・`combo_calibrators` は全廃済み。
  名前が残っていないか `grep` する
- **`hooks -> components` の逸脱 (toast の 5 件) は既知。**規約に「あえて残す」と
  書いてある。**これを毎回言わない**

## 溜まったものの扱い

**消す提案には根拠を付ける。** 最低でもこの 2 つ:

```bash
git log --oneline -3 -- <パス>     # 最後に触ったのはいつか
grep -rn "<ファイル名やシンボル>" backend/src frontend/src backend/tests
```

**`backend/tests/` を必ず grep に含める。**規約の `code.scope` は tests を
外しているので、道具には「テストからだけ使われているもの」が
**使われていない**ように見える(台帳に実例がある:
`ai/core/temperature.py` の `transform_place_scores`)。

枠組みが名前で拾うもの (FastAPI のルータ関数・Lightning のフック・
Alembic の migration) は消さない。規約の `code.dead.entrypoints` に入っている。

## 出す

```
[分ける] backend/src/ai/evaluation/backtest.py (1,071 行 / 上限 550)
切れ目: evaluate() 440-892 が 1 つの関数で 453 行。中で「窓を決める」
        「予測を回す」「券種ごとに集計する」「bootstrap を回す」の 4 つをしている
効き方: 券種を 1 つ足すだけで 453 行を読まされる
手順: /code
```

「このままでよい」も必ず含める。**全部を直せと言うのは、読んでいない証拠。**

## やらないこと

- 消さない・動かさない。**提案だけ**。実行は `/code`
- 行数だけを理由にしない。行数は合図であって理由ではない
- **コメントの厚さを一律に減らせと言わない。**このリポジトリは判断の根拠
  (実測値・否定された仮説・踏んだバグ)をコードの隣に残す方針で、台帳に
  そう記録されている。減らすなら「これは言い換えだ」と 1 件ずつ示す
- 好みの書き方を規約のように言わない
