**コミットになる前の差分**を片づける。docs も、コードの形も、それぞれ別の役が
見ているが、**まだコミットになっていない仕事**は誰も見ていない。

## 0. 先に確かめる — このリポジトリは同時に触られている

`CLAUDE.local.md` に書いてあるとおり、**複数の Claude セッションが同じ
クローンで動きうる。**`git` の `checkout` / `reset` / `stash` は
**明示の合意なしにやらない。**このコマンドがやってよいのは `add` と `commit` だけ。

```bash
git status --short
```

**自分が触っていないファイルが差分に入っていたら、そこで止めて報告する。**
別のセッションの作業中かもしれない。

## 1. 差分を取る

```bash
git diff HEAD --stat
```

`--since <ref>` があれば `git diff <ref>` を起点にする。
差分が無ければ、ここで終わる(何もしない)。

## 2. 読ませる

`.claude/agents/reviewer.md` へ、**差分の起点だけ**を渡して投げる。
**要約して渡さない** — 要約した時点で、自分が重要だと思ったものしか見られない。

## 3. 秘密を確かめる

これだけは agent 任せにせず、**必ず自分でも見る。**

```bash
git diff HEAD | grep -nEi '(api[_-]?key|secret|token|password|BEGIN [A-Z ]*PRIVATE KEY)'
```

1 件でも出たら、そこで止めて報告する。**コミットしない。**

`data/*.db` と `data/models/` は `.gitignore` の内側にある。
**差分に出てきたら、それ自体が所見**(除外が外れている)。

## 4. 通るか確かめる

差分が触った側だけ回す。両方触っていれば両方。

```bash
# backend
cd backend && uv run pytest && uv run ruff check src tests

# frontend
cd frontend && pnpm test && pnpm lint
```

**通らないままコミットの話をしない。**

`main.py` に router を足した差分では、**テストが 404 のまま通ることがある**
(wheel に複製されるため)。その場合は
`cd backend && uv pip install -e . --no-deps --offline` を挟んでから回し直す。

## 5. 直す

reviewer の指摘を 3 つに分ける。

| 仕分け | どうするか |
|---|---|
| **壊れる** | いま直す。直してから次へ |
| 残骸(デバッグ出力・コメントアウト・使わない import) | いま消す |
| 好み・構造 | 直さない。`/code` に回す |

**壊れるものを直したら、その差分をもう一度見る。**直しが新しい残骸を作る。

## 6. コミットの切り方

1 コミット = 1 つの目的。**混ざっていたら分ける。**

```
1) <パス群>   <何をしたか>
2) <パス群>   <何をしたか>
```

**一覧を見せて承認を取ってから**コミットする(`$ARGUMENTS` に `--commit` が
あっても、切り方は必ず見せる)。`--commit` が無ければ、切り方を出すだけで止まる。

メッセージは**何をしたか**を書く。「fix」「update」「wip」で終わらせない。
このリポジトリは `feat(ui):` `refactor(api):` `fix(scripts):` `docs:` の形で
書かれている。**日本語の本文で、何が変わったかを 1 行。**

## 7. push の前に

作業はふだん `main` に直接積んでいる。**枝を切るかどうかは聞く。**

`push` は**言われたときだけ**。このコマンドは既定では push しない。
**公開リポジトリなので、push は外へ出す行為。**個人研究のデータや
モデルが差分に入っていないことを 3 節で確かめてある前提でだけ通す。

## 報告

- 直したもの / 回したもの / 切ったコミットとその理由
- **読み切れなかった範囲**(あるなら正直に)
