**「書いてあるから正しい」を一度も使わない。**docs は実装より先に古びる。
ここは、ずれを見つけて直すところ。

## 1. 対象を決める

```bash
K=$(ls ~/.claude/plugins/cache/*/claude-keeper/*/scripts/k.py 2>/dev/null | head -1)
[ -n "$K" ] && python3 "$K" check --only docs || echo "claude-keeper 未導入。機械の候補なしで進める"
```

| 引数 | 対象 |
|---|---|
| なし | 未コミットの差分に関わる文書 **+ `check --only docs` が出した指摘ぜんぶ** |
| ファイル名 | それだけ |
| `--since <ref>` | その参照からの差分 |
| `--read-only` | 読んで報告するだけ。直さない |

**「差分が無いから対象が無い」で終わらせない。**差分に何も無くても、機械が出した
指摘(散らばり・伸びた節・置き場所・索引)は対象に入る。ここを差分だけに絞ると、
**動きの止まっている文書の散らかりは永久に出てこない。**

### 初めて回すとき / 半年ぶりに回すとき

差分ではなく**棚卸しをする。**機械の指摘が 0 件でも、これだけは自分で見る:

1. `docs.layout` の `role` を読み、**各文書を開いて、その役割どおりの中身か**
   確かめる。役割から外れた節は、正しい文書へ出す候補
2. `CLAUDE.md` を全文読む。**そこにある必要があるか**を節ごとに問う
   (skill `claude-md`)。設計・仕様・実験の記録は `docs/` の仕事
3. 出す先が `layout` に無ければ、**`layout` に足してから**出す

## 2. 読ませる

`.claude/agents/docs-auditor.md` へ投げる(会話の経緯は渡さない)。

**読む順番が肝心** — docs を先に読み、実装を見る前に「これが本当なら何ができる
はずか」を書き出す。逆順だと、docs の記述を実装で補って読んでしまい、
**足りない記述と間違った記述が両方とも見えなくなる。**

| 見るもの | 判定 |
|---|---|
| docs にあり、実装にある | 合っている |
| docs にあり、実装に無い | **嘘。いちばん高くつく** |
| docs に無く、実装にある | 抜け |
| docs にあるが、動かすと違う | 古い。**動かして確かめる** |

### このプロジェクトで特に食い違いやすいところ

- **廃止したものの名前が残る。**EV (`min_ev` / `win_ev_threshold`)・Kelly
  (`kelly_bet_size` / `--bet-sizing`)・`STRATEGY_PRESETS`・`stake_units`・
  `enabled_bet_types`・`combo_calibrators`・旧 ai の nn サブパッケージ は**存在しない**
- **回収率の数字。**測り直すたびに動く。**窓 (期間・レース数) が書かれていない
  数字は、それ自体が所見**。`--start` を省いた backtest は in-sample の値を出す
- **設定項目。**`docs/spec.md` の API 仕様と実際の応答がずれる
  (`_dict_to_response` がキー名を取りこぼしても pydantic は黙って捨てる)
- **`docs/archive/` は「古い」ではない。**記録なので、いまの仕様と
  食い違っているのが正しい。規約の `archive.rules` どおり、**否定された仮説は
  消さずに archive へ送る**（理由を書かないと同じ実験をもう一度回すことになる）

## 3. 直す

**書き換える前に一覧を見せて承認を取る。**種類ごとに手順が違う。

### 実装に合わせる

- **変更の中身を実際に読んでから書く。**ファイル名だけで docs を書き換えない
- **最小差分。**周りの文章は整えない(整えると差分が読めなくなる)
- 実装履歴は `docs/archive/2026.md` にだけ書き、仕様書には**結論だけ**残す
- 最後に**何を書かなかったか**とその理由を報告する

### 置き場所と索引を整える

中身の書き換えはしない。移動と索引だけ。

1. 索引から辿れない / 規約にない場所 / リンク切れ / 内容が重なっているものを拾う
2. **「移動 / 統合 / 削除 / 残す」の一覧を先に出して承認を取る**
3. `git mv` で動かす(履歴を切らない)
4. `docs/README.md` を書き直し、**リンク切れを全部直す**
5. 規約の `docs.layout` を実態に合わせる

### 散らばりと二重管理を寄せる

**先に `.claude/agents/duplication-auditor.md` へ投げる**(会話の経緯は渡さない)。
**機械が拾うのは字面がそろっているものだけで、言い換えて写したものは出ない。**

寄せるかどうかは skill `single-source` の判定で決める —
**字面ではなく、変わるときに一緒に変わるかで見る。**

| 読んでみたら | どうするか |
|---|---|
| 同じ事実が 2 か所以上にある | **寄せ先を 1 つ決める。**他は寄せ先を指す 1 行にする |
| 同じ事実だが内容が違う | **どちらが正か実物で確かめてから**寄せる。新しいほうを正としない |
| 同じ量だが窓が違う | **別物。触らない。**ただし窓を明示する |
| 片方だけ直しても両方正しいまま | **別の事実。触らない** |
| CLAUDE.md の節が読み物になっている | `docs/` へ全文出し、CLAUDE.md には 1 行残す |

このリポジトリの寄せ先:

| 話 | 正本 |
|---|---|
| 動かすコマンド・再学習・バックアップ | `docs/operations.md` |
| API・DB スキーマ・ディレクトリ構成 | `docs/spec.md` |
| 層と依存の向き・画面構成・状態管理 | `docs/design.md` |
| 損失・特徴量・買い方・実験の結果 | `docs/ai-model.md` |
| 取り込み・レート制御・robots.txt | `docs/data-pipeline.md` |
| 作品としての説明 | **`portfolio-site` の `projects.ts`**(README の生成元) |

- **`README.md` の `portfolio:begin` 〜 `portfolio:end` は直さない。**
  生成物なので、次の生成で消える。直すなら生成元
- **切り出すときは全文を移す。要約しない。**要約したぶんは失われる
- 移したあと、元の場所には**「どこへ行ったか」の 1 行**を必ず残す
- 寄せ終えたら `check --only docs` を回し直す。**残っていれば寄せ切れていない**

### 長さと文体を直す

skill `docs-style`(禁止事項リスト)がそのまま作業指示。**削る前に仕分ける:**

| 種類 | 行き先 |
|---|---|
| いまの仕様・設計・手順 | **残す**(文体だけ直す) |
| 実装履歴・没案・日付つきの経緯 | **`docs/archive/2026.md` へ移す**(消さない) |
| 空虚な前置き・重複した要約・一般論 | **消す** |

**箇条書きが 5 個以上並んで各項目に説明が付いていたら表にする。**

## 4. 記録 (archive) の扱い

- 記録に対しては「archive 送り」ではなく**「割りどき」**と言う
- 割るのは期間で。`git mv` で分け、**`docs/archive/README.md` に 1 行足す**
- **中身は一切書き換えない**

## 5. 確かめる

- **消した情報が本当に不要か。**判断・罠・警告・動くコマンドを消していないか
- **リンク切れを作っていないか。**消した節に他から飛んでいないか grep する
- **同じ事実を書いている他の文書を直したか**
- 記録へ移したぶんが `docs/archive/README.md` から辿れるか

## 6. 判断を残す

直さないと決めたものは `.claude/judgments.yml` へ(書式は `/code` の 5 節)。

## 7. 報告

- ファイルごとに **「507 行 → 480 行」** の形で
- 記録へ移した項目の件数と行き先
- **消したもののうち、判断が微妙だったものを 2〜3 件**(戻せるように)
- **書かなかったこと**とその理由
- **寄せた話と寄せ先**
