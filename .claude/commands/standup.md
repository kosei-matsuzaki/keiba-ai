`.claude/agents/` にいる役を**並列に**走らせて、1 枚にまとめる。運用の本体。

**役をサブエージェントに投げるのは、速いからではない。**この会話で自分が書いた
コードに肩入れさせないため — 会話の記憶を持たない立場で読ませる
(skill `flat-view`)。だから、**役に会話の経緯を渡さない。**
渡した時点で意味が消える。

## 1. 誰を走らせるか

```bash
ls .claude/agents/
```

このプロジェクトにいるのは
**docs-auditor / duplication-auditor / code-steward / critic / reviewer** の 5 役。

| 引数 | 対象 |
|---|---|
| なし | 全役 |
| 役名 | その役だけ(複数可) |
| `--since <ref>` | 差分を見る役 (`reviewer`) の起点を指定 |

## 2. 走らせる

**全役を 1 つのメッセージで、まとめて起動する**(順に投げると直列になる)。

各役に渡すのは次だけ:

- 対象の範囲(パス、または `--since` の起点)
- 今日の日付
- 「会話の経緯は渡さない」という断り

**渡してはいけないもの:** この会話で何を実装したか、なぜそうしたか、
どの実験を回して何が出たか、何を急いでいるか。渡すと、役は作り手の言い分を
前提に読み始める。**とくに `critic` に「この施策は効いた」と伝えない** —
それを疑うために置いた役なので、伝えた時点で席が消える。

`reviewer` には差分の起点だけ渡す。中身を要約して渡さない。

## 3. まとめる

返ってきたものを、**1 枚**にする。役ごとに並べない — 役ごとに並べると
「5 人ぶんの感想文」になって、何をすればいいか分からなくなる。

```
## 今日いちばん効くもの
  <1 件だけ。誰が何と言ったかではなく、何をすると何が変わるか>

## 直す (n 件)
  [壊れる] ...(reviewer)                → いま
  [嘘]     ...(docs-auditor)            → いま
  [伸びた] ...(code-steward)            → 区切りのとき

## いまは直さない (n 件)
  ... 理由 ...

## 割れた
  <役どうしで食い違ったところ。どちらが証拠を持っているか>
```

**複数の役が別の面で同じことを言っていたら、そこが見出し。**
1 件ずつ並べると小さく見えるものが、束ねると大きい。

このプロジェクトで束ねやすいのは、**同じ事実が CLAUDE.md と docs に
分かれている**という形。`docs-auditor` は「散」、`duplication-auditor` は
「言い換え」、`reviewer` は「片方だけ直っている」として、
**同じ 1 か所を別の言葉で指してくることがある。**

**役どうしが割れたら、割れたまま出す。**片方に寄せて 1 つの意見にしない
(割れていること自体が、その論点が難しいという情報)。ただし
**同じ言葉で違う面を指しているだけ**のことがあるので、割れたと言う前に
それぞれが何を見たかを確かめる。

## 4. 決めたことを残す

「いまは直さない」に入れたものは、**必ず `.claude/judgments.yml` に書く。**
書かないと、次の standup で同じことを言われる。3 回言われたら黙らされる。

```yaml
judgments:
  - path: backend/src/ai/evaluation/backtest.py
    key: "long_function:evaluate"
    decision: "いまは分けない"
    why: "窓の決め方を変える実験が走っている。落ち着いてから切る"
    at: 453
    date: 2026-09-05
```

claude-keeper が入っているなら
`python3 <claude-keeper>/scripts/k.py judge --key ... --why ...` でも書ける
(同じ鍵があれば差し替えてくれる)。

## やらないこと

- **直さない。**standup は状態を出すところ
- 役の出力をそのまま貼らない。**まとめる**のがこのコマンドの仕事
- 件数で凄みを出さない。「23 件」は判断ではない
