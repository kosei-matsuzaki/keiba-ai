# Part A — テーマを作り替える

## A-0. なぜ似すぎたのか（切り分け）

第2版で入れたものには、**普遍的な作法**と**ポートフォリオ固有の意匠**が混ざっていました。
前者は残し、後者だけを取り替えます。

| 第2版で入れたもの | 判定 |
|---|---|
| 箱をやめて罫線で区切る | **残す** — 密度の高い道具に有効な作法 |
| 角丸 2px | **残す** — 計器らしさ |
| 数値を等幅 + `tabular-nums` | **残す** — 桁が揃うのは実利 |
| 余白と型を数段に絞る | **残す** — 設計の基本 |
| **青一色（`206 100% 74%` アイスブルー）** | **取り替える** ← 最大の要因 |
| **方眼紙の背景（`.bg-grid`）** | **やめる** ← ポートフォリオの署名そのもの |
| **`§NN` の章番号** | **取り替える** ← 同上 |
| **等幅・大文字・字間 0.22em のラベル** | **弱める** ← 同上 |
| **「色は 1 つだけ」という原則** | **捨てる** ← この題材には合っていない |

最後の 1 行が重要です。ポートフォリオは**読み物**なので色を削るのが正解でした。
KEIBA AI は**お金と確率を扱う道具**なので、**色は情報そのもの**です。
「色を使わない」を守った結果、この作品らしさまで消えていました。

## A-1. 新しい方向：「ナイター開催のオッズ端末」

> 研究ノートではなく、**場立ちの端末**。暗がりに数字と枠色が光っている画面。

第2版の「計測レポート」から一段ずらします。狙いは次の 3 つです。

1. **地は暖色寄りのほぼ黒**（青黒 → 炭）。同じ「暗い」でも温度が違うと別物に見える
2. **アクセントは琥珀（オッズ・金額・的中）**。アイスブルーの対極で、賭けの題材に合う
3. **色に意味を持たせる** — 枠色 / 損益 / 推奨。無彩色一辺倒をやめる

## A-2. 署名になる意匠を差し替える

ポートフォリオの署名は「方眼紙 + §NN + 大文字等幅ラベル」でした。
KEIBA AI には**この題材にしか作れない意匠**があります。

### ① 枠色（最重要・これが新しい顔になる）

JRA の枠番には固有色があります（1白 2黒 3赤 4青 5黄 6緑 7橙 8桃）。
**馬番を枠色のチップで出すだけで、一目で「競馬のアプリ」になり、しかも実用的です**
（利用者は枠で馬を識別するため）。ポートフォリオには絶対に作れない意匠でもあります。

```ts
// lib/waku.ts
export const WAKU = [
  { bg: '#f5f5f5', fg: '#111111', name: '白' },  // 1
  { bg: '#1a1a1a', fg: '#f5f5f5', name: '黒' },  // 2
  { bg: '#d43b3b', fg: '#ffffff', name: '赤' },  // 3
  { bg: '#2f6fd0', fg: '#ffffff', name: '青' },  // 4
  { bg: '#e8c33a', fg: '#111111', name: '黄' },  // 5
  { bg: '#3fa860', fg: '#ffffff', name: '緑' },  // 6
  { bg: '#e08a2e', fg: '#111111', name: '橙' },  // 7
  { bg: '#e39ab5', fg: '#111111', name: '桃' },  // 8
] as const;

/** 馬番 -> 枠番。JRA の標準的な割り当て（余りは外枠から 1 頭ずつ増える）。 */
export function wakuOf(umaban: number, runners: number): number {
  if (runners <= 8) return umaban;
  const base = Math.floor(runners / 8);
  const extra = runners % 8;            // 後ろ extra 枠が base+1 頭
  const boundary = (8 - extra) * base;  // ここまでが base 頭ずつの枠
  return umaban <= boundary
    ? Math.ceil(umaban / base)
    : 8 - extra + Math.ceil((umaban - boundary) / (base + 1));
}
```

```tsx
// components/Umaban.tsx
export function Umaban({ n, runners }: { n: number; runners: number }) {
  const w = WAKU[wakuOf(n, runners) - 1];
  return (
    <span
      className="inline-flex h-6 w-6 items-center justify-center rounded-[2px] font-mono text-[12px] font-bold tabular-nums"
      style={{ background: w.bg, color: w.fg }}
    >
      {n}
    </span>
  );
}
```

検算済みです（8/9/12/16/17/18 頭で枠ごとの頭数が 1 頭差以内に収まり、
18 頭立ては 枠7 = 13・14・15 / 枠8 = 16・17・18 という JRA の実際の割り当てと一致）。

> **ただし暫定です。** 本来は取得元に枠番があるので、**スクレイパー側で取って API に載せるのが
> 正しい**です（`EntrySummary` に 1 列足す）。馬券種に `枠連` がある以上いずれ必要になりますし、
> 除外馬が出たときは馬番と頭数からの導出が実際とずれます。

**使う場所**: レース詳細の表、レース一覧の「AI 予想」列、推奨買い目、Ledger の買い目表示。
**使わない場所**: それ以外。枠色は馬番専用の語彙にして、他に流用しないこと。

### ② 番号は `§NN` ではなく `R`

章番号はポートフォリオの語彙です。この題材には**レース番号**という固有の番号があります。

- レース詳細の見出しは `§02 RACE DETAIL` ではなく **`11R`**（大きく・琥珀）
- 一覧の行頭も `11R`
- 画面（Dashboard / Ledger / Models / Settings）には**番号を振らない**。
  番号が意味を持つのはレースだけです

### ③ ラベルは大文字をやめ、字間を詰める

`uppercase tracking-[0.22em]` はポートフォリオの署名です。同じ等幅でも印象を変えます。

```
旧（ポートフォリオ）: font-mono text-[10px] uppercase tracking-[0.22em]
新（KEIBA AI）:       font-mono text-[11px] tracking-[0.04em] text-subtle-foreground
```

大文字化をやめると和文ラベル（`単勝回収率`）との差もなくなり、混在が自然になります。

### ④ 方眼をやめ、代わりに「罫」を使う

`.bg-grid` は削除します。代わりに、**競馬新聞の罫**を思わせる区切りを使います。

- セクション見出しは、見出しの右へ罫線が伸びる形
- 表の**ヘッダ下だけ 2px の罫**（`border-b-2 border-border-strong`）。他は 1px
- 開催場ごと、レースごとの区切りに**太さの差**を持たせる

## A-3. トークン（`.dark` ブロックを差し替え）

## A-4. 密度を上げる（ここも差別化）

ポートフォリオは読み物なので余白が広い。**KEIBA AI は逆に詰めるほど「プロの道具」に見えます。**

| 対象 | 現在 | 新 |
|---|---|---|
| 表の行の高さ | 約 44px | **32px**（`py-1.5`） |
| 表の文字 | `text-sm`（14px） | **13px**、数値は 13px 等幅 |
| 表ヘッダ | `text-[10px]` 大文字 | 11px・大文字なし |
| セクション間 | 48px | **32px**（表の多い画面） |
| 本文（説明文） | `leading-relaxed` | 変えない（読み物は読み物のまま） |

「余白を広げる」は見出しまわりだけ。**表の内部には持ち込まない**（第2版 §8 と同じ方針）。

# Part B — 全画面の UX

体裁とは別に、**触ったときの手数と迷い**を減らします。効果の大きい順に並べています。

## B-1. 全画面に効くもの

### ① 「AI 予想を実行」の 2 段階をやめる（最優先）

いまレース詳細を開いた利用者は、**目的（予想を見る）に着くまでにボタンを 2 回押します**。

```
レース詳細を開く -> [出馬表を取得] を押す -> 待つ -> [AI 予想を実行] を押す -> 待つ -> やっと予想
```

しかも `handleRunAi` は「1 回目は `setAiRequested(true)`、2 回目以降は `refetch`」という
**同じボタンで意味が変わる**作りで、押した人には区別が付きません。

**指示:**

- ボタンを **`予想を見る` の 1 つ**にする。押したら
  「出馬表が無ければ取得 -> 完了を待つ -> 予想を実行」まで**連鎖させる**
- 進捗は 1 本のバーで `出馬表を取得中… -> 予想を計算中…` と段階名を出す
- 2 回目以降は文言を `予想を更新`（＋最終実行時刻を併記）に変える。
  **同じ文言のまま挙動を変えない**
- 一覧側の `AI 予想を実行` も、**その日のタブを開いた時点で自動実行**にする。
  手動のままにするなら、理由（時間・負荷）をボタンの下に一言添える

### ② 実行中のジョブがページを離れると失われることを伝える

`api/jobs.py` の `JobRegistry` はインメモリで、**バックエンドを再起動するとジョブ状態が消えます**
（`CLAUDE.md` に明記）。いまの UI はそれを知らせないので、利用者は「固まった」と受け取ります。

**指示:**

- 長時間ジョブ（ingest / train）の実行中は、
  「**この実行はバックエンドを再起動すると追跡できなくなります**」を進捗の下に小さく出す
- ポーリングが一定回数連続で失敗したら、
  「ジョブの状態を取得できなくなりました。バックエンドが再起動された可能性があります」
  ＋ `再確認` ボタンに切り替える。無言で回り続けない
- 直近の実行結果（job_id・開始時刻・結果）を `localStorage` に 1 件残し、
  再訪時に「前回の実行: 成功 / 12:04」と出す

### ③ 失敗したトーストから再試行できるようにする

いまは `toast.error('保存に失敗しました: …')` で終わりです。利用者は**同じ操作をやり直す**しかない。

```tsx
toast.error('保存に失敗しました', {
  description: msg,
  action: { label: '再試行', onClick: () => mutation.mutate(values) },
});
```

失敗しうる操作（設定保存・ingest・学習・予想）すべてに付けてください。

### ④ 破壊的操作の確認を揃える

`DeleteModelDialog` はありますが、**モデル名を打たせる**ところまではしていません。
学習済みモデルは再作成に時間が掛かるので、削除だけは**名前の確認入力**を挟む価値があります。

### ⑤ キーボードで触れるようにする

密度の高い道具は、キーボードで動くと一段「プロの道具」になります。

- 表の行に `tabIndex={0}` と `onKeyDown`（Enter/Space で遷移）。
  いま `role="button"` は付いていますが**キーで押せません**（アクセシビリティ上も問題）
- `j` / `k` で行移動、`Enter` で詳細、`Esc` で戻る
- `?` でショートカット一覧を出す

### ⑥ 読み込み中の形を本番と合わせる

`Skeleton` が `h-32 w-full` のような塊だと、表示された瞬間にレイアウトが跳ねます。
**表のスケルトンは表の形**（ヘッダ + N 行）で出してください。

## B-2. Dashboard

**問題**: 指標が並んでいるだけで、**次に何をすればいいか**が書かれていません。
週末にレースが未取得でも、モデルが古くても、画面は同じ顔をしています。

**指示:**

1. 最上部に **「いまの状態」の 1 行**を置く。条件で文言が変わる帯にする
   - 今週末のレースが未取得 -> `今週末のレースがまだ取り込まれていません` ＋ `取得する`
   - active モデルなし -> `有効なモデルがありません` ＋ `学習する`
   - 直近の ingest が失敗 -> `前回の取り込みが失敗しています` ＋ `詳細`
   - すべて正常 -> 出さない（**問題がないときは何も出さない**）
2. **KPI をクリックできるようにする**。`NDCG@3` -> Models、`単勝回収率` -> Ledger へ
3. 指標名に説明を付ける。`NDCG@3` は一般に通じません
   （`上位3頭の並びの正確さ（1.0 が完全一致）` 程度の一言をツールチップで）
4. グラフの期間（180日）を切り替えられるようにする（30 / 90 / 180 / 全期間）
5. active モデルの**学習日と評価期間**を目立たせる。「いつのモデルか」は判断に直結します

## B-3. Race 一覧（`UpcomingRaces`）

**問題**: 一覧の目的は「**今日どのレースを見るべきか**」の判断ですが、
いまは全レースが等価に並び、AI 予想は最終列に小さな文字で出るだけです。

**指示:**

1. **「買い候補あり」を一覧で示す。** 単勝 EV > 1.1 の馬がいるレースに印を付ける
   ```tsx
   <span className="font-mono text-[11px] text-success">◎ 2</span>   // 買い候補 2 頭
   ```
   これが一覧の存在価値になります。今は詳細を全部開かないと分かりません
2. **AI 予想列を枠色の馬番チップに。** `formatTopHorses` の文字列より、
   `<Umaban>` を 3 つ並べるほうが速く読めます（A-2 ①）
3. **開催場で絞れるようにする。** いまは複数開催が縦に全部積まれます。
   日付タブの下に開催場のチップ（`札幌 12R / 新潟 12R / 小倉 12R`）を置き、
   選択で絞る。既定は全部
4. **並べ替え**（R 順 / 発走時刻 / EV 順）。EV 順が使えると一覧が「予想リスト」になります
5. **発走時刻を出す**。`RaceSummary` に無いので、スクレイパーと API に 1 列足す必要があります。
   時刻順に並ぶだけで一覧の実用性が上がります
6. 行の hover / focus を効かせ、キーボードで開けるようにする（B-1 ⑤）

## B-4. Race 詳細（`RaceDetail`）

**問題**: 18 頭 × 13 列を横スクロールで読ませていて、**結論がどこにあるか分かりません**。

**指示:**

1. **結論を表の上に出す。** 表を読ませる前に、AI の推奨を 2〜3 行のカードで
   ```
   推奨   ⑥ ビザンチンドリーム   単勝 EV 14.76   単勝確率 47.6%   オッズ 31.0
          ⑰ レガレイラ           単勝 EV  2.24   単勝確率 35.0%   オッズ  6.4
   ```
   `RecommendationsCard` は既にありますが、**表の下ではなく上**に置いてください
2. **左 2 列（馬番・馬名）を固定**する（`sticky left-0`）。横スクロールしても馬が分かる
3. **なぜ推奨なのかを見せる。** `EV = 単勝確率 × オッズ` の式をツールチップに出すだけで、
   「AI がなんか言っている」から「計算が見えている」に変わります
4. **オッズの鮮度を出す。** `オッズ更新` ボタンの隣に `12:04 時点`。
   賭ける判断に直結するのに、いまは分かりません
5. **レース後は答え合わせをする。** 着順と払戻が入ったら、
   「推奨した 2 頭のうち 1 頭が 1 着 / 単勝 3,100 円 / この予想の回収率 155%」を出す。
   **これは他の競馬アプリにない、この作品ならではの機能**です（回収率で評価する設計と一致する）
6. 出馬表が無いときの空状態を、**取得ボタン付き**にする（いまはヘッダのボタンのみ）
7. 前後のレースへ移動（`<- 10R / 12R ->`）。1 開催を順に見る動線が今はありません

## B-5. Ledger（収支）

**問題**: 収支管理は「**勝っているか負けているか**」が一目で分かるべきですが、
いまは表と内訳が並んでいるだけです。

**指示:**

1. **最上部に損益を大きく出す。** 期間の `投資 / 払戻 / 収支 / 回収率` を 4 つ、
   収支と回収率は**損益色**（プラス緑・マイナス赤）で。回収率は 100% に基準線を引く
2. 資金推移グラフに **100%（損益分岐）の水平線**を引く。今は上下しているだけで基準が無い
3. **期間フィルタとグラフを連動**させる。フィルタを変えたらグラフも同じ期間に
4. 内訳（券種別）は**回収率で降順**に並べる。件数順より意思決定に使えます
5. 手入力（`AddBetDialog`）は、**レース詳細から直接呼べる**ようにする。
   予想を見て -> 買った -> 記録、が同じ画面で完結します
6. CSV は書き出しだけでなく**読み込み**も。他で付けていた記録を持ち込めます

## B-6. Models / ModelDetail

**問題**: どれが有効で、どれが最良かが分かりにくく、学習の進捗も見えません。

**指示:**

1. 一覧を**評価指標で並べ替え可能**にし、`active` を左端の印で示す
2. **2 つ選んで比較**できるようにする。指標を横に並べるだけでよい。
   `log_growth` / `multi` / `plackett_luce` を比べた過程がそのまま作品の見どころになります
3. 学習は長時間ジョブ。**進捗（エポック / 経過 / 残り推定）とログの末尾**を出す。
   途中で**中断**できるようにする
4. モデル名を `20260613T114800-nn` のまま出さず、
   **`損失 / 学習期間 / 監視指標`** を並べて識別できるようにする
5. `ModelDetail` に**学習時の設定**（`--loss` `--monitor` `--train-end` など）を全部出す。
   再現できることが分かるのは、この作品の主張と直結します

## B-7. Ingest

**問題**: 長時間ジョブなのに、いつ終わるかが分かりません。

**指示:**

1. 進捗を **`342 / 1,200 レース（28%）・経過 12 分・残り約 31 分`** の形で
2. **中断**できるようにする（`scraper/stop_flag.py` が既にあるので UI から呼ぶだけ）
3. robots.txt で拒否されたときは、**失敗ではなく「10 分後に再試行します」**と出す
   （fail-closed で 10 分後に再試行する実装になっている）
4. 期間 ingest は resume 対応（`jobs.ingest_range`）。
   **「前回の続きから」を UI にも出す**。手で日付を入れ直させない

## B-8. Settings

**問題**: 設定項目が何に効くのか分からず、保存バーが常に出ています。

**指示:**

1. **変更が無いときは保存バーを出さない**（`isDirty` で出し分け）。
   常時出ていると「未保存かどうか」の情報が失われます
2. 各項目に**「これを変えると何が起きるか」**を 1 行。特に
   `fractional Kelly の係数` `最低 EV` `最大投資額` は結果に直結します
3. 危険な値には**その場で警告**を出す（Kelly 係数を 1.0 にする、上限を外す等）
4. タブのラベルを揃える（`Ingest` だけ英語 -> `取込`）
5. 保存後は**何が変わったか**をトーストに出す（`最低EVを 1.05 -> 1.10 に変更しました`）
